# Instances

An instance is a Minecraft game directory with an exact Minecraft version and
loader selection. Each instance has its own mods, saves, configuration, and
logs. Ephervex reuses downloaded game files, libraries, assets, and managed
Java runtimes across instances.

## Choose temporary or persistent storage

New instances are **temporary** by default. They live in the operating
system's temporary directory. Closing the game does not delete them, but the
operating system can clear that directory at any time. Use temporary storage
for a test you can discard.

:::note
Choose persistent storage for worlds or test results you need to keep. The
operating system can remove temporary instances without asking Ephervex.
:::

Choose **persistent** storage when you want the instance to remain in your
configured instance folder. You can also move a stopped temporary instance
there later with **Make Persistent**. Its mods, saves, logs, and name move with
it. Linked temporary servers move too unless you choose to leave them behind.

## Create an instance

Choose the exact Minecraft release you need. Vanilla needs no loader build;
Forge and NeoForge need an exact build that supports that release. Ephervex
does not replace an unsupported selection with another version. For Minecraft
1.12.2, Forge builds older than 14.23.5.2851 use an installer format Ephervex
does not support. They are not offered, and selecting one by exact version is
refused.

<Tabs groupId="interface" queryString="interface">
<TabItem value="gui" label="Desktop" default>

On **Instances**, select **New Instance** and enter a name. Then:

1. Choose the Minecraft release you need.
2. Choose Vanilla, Forge, or NeoForge. For Forge or NeoForge, select the exact
   loader build below the loader choice.
3. Choose temporary storage for a disposable test, or turn on **Store
   persistently** to keep the instance. Select **Create Instance**.

<ThemeScreenshot state="create-instance-dialog" region="dialog" callouts={createInstanceCallouts} alt="New Instance dialog: 1 marks the Minecraft release, 2 marks the loader build, and 3 marks the persistent storage choice" />

</TabItem>
<TabItem value="cli" label="CLI">

Replace `VERSION` with an exact Minecraft release:

```bash
ephervex instance create "Test World" --minecraft VERSION
```

For Forge or NeoForge, supply the exact loader build. Add `--persistent` if
you want to keep the instance under the persistent instance root:

```bash
ephervex instance create "Mod Test" --minecraft VERSION --loader neoforge --loader-version LOADER_BUILD --persistent
```

`--temporary` explicitly selects the default temporary storage.

</TabItem>
</Tabs>

## Find and launch an instance

You need an [account](./accounts.mdx) before launching. The first launch
downloads missing game files. Ephervex picks a compatible Java runtime unless
one is [pinned](#set-java-and-memory-for-one-instance). The workspace header
shows that runtime and its status. A launch Ephervex refuses names the runtime
it tried, how it was chosen, and the Java the instance expects.

<Tabs groupId="interface" queryString="interface">
<TabItem value="gui" label="Desktop" default>

Find the instance on **Instances** and select **Launch** on its card. Select
the card or **Open Workspace** to inspect its mods, settings, logs, and other
details. The **Running** page shows active clients and their controls.

<ThemeScreenshot state="instances-overview" region="client-card" alt="Instance card with its version, storage type, state, and Launch button" />

</TabItem>
<TabItem value="cli" label="CLI">

```bash
ephervex instances list
ephervex instance show INSTANCE_ID
ephervex launch INSTANCE_ID
```

Use the ID from `instances list`. The launch command stays attached to the
game process and reports its exit status when it ends.

</TabItem>
</Tabs>

## Search, filter, and sort instances

Searching, filtering, and sorting change only what the list shows.

<Tabs groupId="interface" queryString="interface">
<TabItem value="gui" label="Desktop" default>

On **Instances**, type in **Filter instances...** to search names, Minecraft
versions, loaders, sources, and group names. **All**, **Temporary**, and
**Persistent** choose the storage type, and **Favorites** shows only
favorites.

Select **Filters** to narrow the list by Minecraft version, loader, running
state, linked servers, or group, and to choose **Sort by**: **Favorites
first**, **Name**, **Minecraft version**, or **Loader**. Ephervex remembers
the sort order. While anything narrows the list, the header shows a count such
as "3 of 8 instances", and **Clear filters** resets everything except the
sort order.

<ThemeScreenshot state="instances-filters" alt="Instances narrowed to NeoForge with the Filters panel open, the header showing 3 of 8 instances, and Clear filters" />

</TabItem>
<TabItem value="cli" label="CLI">

```bash
ephervex instances list --search TEXT
ephervex instances list --favorite --loader neoforge --running
ephervex instances list --group GROUP_NAME --sort name
```

Every option you give must match. Other filters are `--minecraft VERSION`,
`--stopped`, `--ungrouped`, and `--linking paired|servers|none`. `--sort`
takes `favorite`, `name`, `minecraft`, or `loader`; without it, the list uses
the order chosen in the desktop app. Favorites are marked `[favorite]` and
grouped instances `[group: NAME]`.

</TabItem>
</Tabs>

## Mark favorites and set icons

Favorites, groups, and icons change only how Ephervex shows an instance or
server. They never move files, and you can change them while the game runs.
Favorites are listed first on **Instances**, with the default sort order, and
on **Servers**. An icon replaces the loader or server symbol on the card, in
the inspector, on **Running**, and in the workspace.

<Tabs groupId="interface" queryString="interface">
<TabItem value="gui" label="Desktop" default>

Select the star beside an instance's or server's name, or **Add to
favorites** in its card menu. To set an icon, select **Choose icon...** in the
card menu, or **Choose icon** under **Organization** in the instance
inspector, and pick a PNG or JPEG image. **Remove icon** brings back the
symbol.

<ThemeScreenshot state="instance-organization" alt="Instances with two favorites listed first, group labels beside the names, and an instance showing a custom icon" />

</TabItem>
<TabItem value="cli" label="CLI">

```bash
ephervex instance favorite INSTANCE_ID
ephervex instance unfavorite INSTANCE_ID
ephervex instance icon INSTANCE_ID IMAGE_FILE
ephervex instance icon INSTANCE_ID --clear
```

For a server, use `server favorite`, `server unfavorite`, and `server icon`
with a `SERVER_ID`.

</TabItem>
</Tabs>

An icon file can be at most 16 MiB, 8192 pixels on a side, and 16 megapixels.
Ephervex keeps its own copy scaled to at most 256 pixels, so changing the
original file later has no effect.

## Group instances

A group is a label for finding instances. An instance is in at most one group;
servers have none. Each group gets one of six colors and keeps it when
renamed. Group names are compared without regard to case. Deleting a group
leaves its instances ungrouped.

<Tabs groupId="interface" queryString="interface">
<TabItem value="gui" label="Desktop" default>

In the instance inspector, choose a **Group** under **Organization**, or
select the close button beside it to remove the instance from its group. In a
card menu, **Set group** lists the groups, and **New group...** there creates
a group with the instance in it.

<ThemeScreenshot state="instance-organization" region="inspector" alt="Instance inspector with a custom icon, the Mod development group, Manage groups..., Choose icon, and Remove icon" />

Select **Groups** on the Instances toolbar, or **Manage groups...** in the
inspector, to see how many instances each group holds. Select **Rename** or
**Delete** on a group, or **New group** to create an empty one. **Delete**
does not ask for confirmation.

<ThemeScreenshot state="instance-groups-dialog" alt="Groups dialog listing three groups with their colors and instance counts, each with Rename and Delete" />

</TabItem>
<TabItem value="cli" label="CLI">

```bash
ephervex groups create GROUP_NAME
ephervex instance group INSTANCE_ID GROUP_NAME
ephervex instance group INSTANCE_ID --none
ephervex groups list
ephervex groups rename GROUP_NAME NEW_NAME
ephervex groups delete GROUP_NAME
```

`instance group` needs a group that already exists. `groups delete` does not
ask for confirmation.

</TabItem>
</Tabs>

## Copy or keep an instance

Duplicate an instance when you want a separate copy to change or test. The
copy starts with the original's storage type. Make Persistent instead when you
want to keep the same temporary instance without leaving a copy behind. Stop
the game before either action. A copy keeps the original's group and icon, but
is not a favorite.

<Tabs groupId="interface" queryString="interface">
<TabItem value="gui" label="Desktop" default>

Open an instance card's menu and select **Duplicate** or **Make Persistent**.
The latter is also available in the instance workspace's **Overview**. When
making an instance persistent, choose which linked temporary servers to move
with it. Duplicate asks whether to retain records of mods missing from the
original's mods folder.

<ThemeScreenshot state="instance-actions-menu" region="actions" alt="Instance context menu with Make Persistent, Duplicate, and Delete Instance actions" />

<ThemeScreenshot state="instance-make-persistent-dialog" alt="Make Persistent dialog with the destination folder and a linked temporary server to move along" />

</TabItem>
<TabItem value="cli" label="CLI">

```bash
ephervex instance duplicate INSTANCE_ID
ephervex instance persist INSTANCE_ID
```

`duplicate` uses the original's storage type. Add `--name "Copy Name"`,
`--temporary`, or `--persistent` to choose a different name or storage type.
By default the copy also records mods the original lists but no longer has in
its mods folder; add `--drop-absent-mods` to leave those out.

`persist` moves all linked temporary servers by default; use `--no-servers` to
leave them in temporary storage, or repeat `--server SERVER_ID` to select
specific servers.

</TabItem>
</Tabs>

## Set Java and memory for one instance

An instance normally follows the global Java, memory, and JVM settings. Pin
values here only when this instance needs different ones. Memory values are
in MiB. Stop the instance before changing these settings.

The runtime's status is **Healthy** when Ephervex picks a runtime that fits or
will download one at launch, **Valid, customized** when a pinned runtime fits,
**Problem** when it cannot run this instance, or **Not checked** when the check
could not run. The expected Java comes from the Minecraft release and loader,
such as `Java 21` or `Java 8, update 320 or older (Forge)`.

<Tabs groupId="interface" queryString="interface">
<TabItem value="gui" label="Desktop" default>

Open the instance workspace, then **Settings**, or select the Java pill in the
workspace header. The **Java runtime** card shows the runtime in use, its
path, how it is chosen, the Java the instance expects, and the status.

<ThemeScreenshot state="client-java-runtime" alt="Java runtime card of an instance that pins a fitting runtime, above the available runtimes" />

When a pinned runtime cannot run the instance, the card shows **Problem** and a
refused launch says why.

<ThemeScreenshot state="client-java-problem" alt="Failed launch notice naming the pinned Java 25 and the expected Java 17, above the Java runtime card marked Problem" />

Under **Available runtimes**, select **Use** on a runtime, or on **Automatic**
to let Ephervex choose. When Settings > Java names a preferred executable, that
entry is **Launcher preference** instead. Runtimes that do not fit are
disabled and say why. To use a runtime Ephervex has not found, enter its path
under **Another Java executable**, select **Check**, then **Use**. Each choice
opens a review of the current and new runtime; nothing changes until you
select **Apply**.

<ThemeScreenshot state="client-java-review" alt="Review of switching an instance from its pinned Java 25 to automatic selection" />

If no installed runtime fits, **Install Java N** installs the Temurin build the
instance expects, even when automatic downloads are off. It does not change the
instance's Java setting. If the instance would not use the new runtime on its
own, a review offers to pin it.

<ThemeScreenshot state="client-java-install" alt="Legacy Forge instance offering Install Java 8 because no installed runtime meets its update ceiling" />

Under **Java and memory**, enter the memory or JVM argument values to override
and select **Save Runtime Settings**. Empty fields follow the global settings.
**Follow Global Settings** removes these overrides; it does not change the Java
runtime choice.

<ThemeScreenshot state="client-settings" alt="Instance Settings with memory and JVM argument overrides" />

</TabItem>
<TabItem value="cli" label="CLI">

View the current overrides and Java status, set the ones you need, or clear
them:

```bash
ephervex instance runtime INSTANCE_ID
ephervex instance runtime INSTANCE_ID --java /path/to/java --min-memory 1024 --max-memory 4096
ephervex instance runtime INSTANCE_ID --clear
```

Without options, `runtime` also prints the runtime the instance would use, the
Java it expects, the status, and any problem. Each option changes only its own
override and keeps the other pinned values. If you specify `--jvm-arg ARG`,
that option replaces the pinned JVM argument list; repeat it for every argument
you want in the list. `--clear` removes every override, including the Java
path.

Install the Java the instance expects without pinning it:

```bash
ephervex java install --instance INSTANCE_ID
```

If the instance would not use the new runtime on its own, the command prints
the `instance runtime` command that pins it.

</TabItem>
</Tabs>

## Change a loader build

For a Forge or NeoForge instance, open its workspace **Overview** and select
**Change Build**. Choose another offered build of the same loader for the
instance's Minecraft release, then select **Install and Switch**. Installed
mods are left in place, so check their compatibility with the new build. Stop
the game first: the button stays available, but the change is refused while the
instance is running.

<ThemeScreenshot state="instance-change-loader-dialog" alt="Change Loader Build dialog with the current build, the build to move to, and a note that installed mods are left as they are" />

Changing a loader build is currently available in the desktop app. It does
not switch between Vanilla, Forge, and NeoForge.

## Inspect a retained pack recipe

An imported instance retains its pack recipe. The CLI can show the client file
plan or the server plan used when creating a linked server. This reads the
retained recipe in the instance; it does not change files or need the original
archive.

```bash
ephervex instance recipe INSTANCE_ID
ephervex instance recipe INSTANCE_ID --side server
```

Optional files that were not selected during import are left out of the
default plan. Add `--all-optional` to include them in the displayed plan. A
manually created instance has no pack recipe; the command reports that without
failing.

## Delete an instance

:::warning
Deleting an instance also removes its linked servers from Ephervex. Decide
whether to keep their directories before confirming. **Delete Files** also
removes saves and server worlds in those directories, and the retained
snapshots of the instance and its servers.
:::

<Tabs groupId="interface" queryString="interface">
<TabItem value="gui" label="Desktop" default>

Stop the game, open the instance card's menu, and select **Delete Instance**.
The dialog lists affected linked servers. Choose **Keep Files** to leave files
on disk, or **Delete Files** to remove the managed directories. While linked
servers are running, the buttons read **Stop and Keep Files** and **Stop and
Delete Files**, and they stop those servers first.

<ThemeScreenshot state="instance-delete-confirmation" alt="Delete Instance dialog listing the linked server it affects, with Cancel, Stop and Keep Files, and Stop and Delete Files" />

</TabItem>
<TabItem value="cli" label="CLI">

```bash
ephervex instance delete INSTANCE_ID
```

The command asks for confirmation before deleting files and names every
linked server. Use `--keep-files` to remove the records while leaving the
directories on disk. In a noninteractive command, use `--yes` to confirm file
deletion. Running linked servers block deletion unless you add
`--stop-linked-servers`.

</TabItem>
</Tabs>
