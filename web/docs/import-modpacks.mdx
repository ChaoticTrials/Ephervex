# Import Modpacks

Ephervex imports Modrinth `.mrpack` archives and CurseForge modpack exports,
and can rebuild a pack from a crash report or `latest.log` whose mod list
records each mod's hashes. It reads the pack's Minecraft release and loader
selection rather than choosing newer versions for you. Other launcher exports, including Prism and MultiMC,
are not supported. The archive is identified by its contents, so changing its
file extension does not change its format. Release builds include the
CurseForge API access needed for imports; no key setup is required.

A pack that pins a Forge build for Minecraft 1.12.2 older than 14.23.5.2851 is
refused before anything is downloaded, because those builds use an older
installer format that Ephervex does not support.

<ThemeScreenshot state="import-modpack-ready" alt="Desktop import review showing the pack, Minecraft release, loader, optional files, and storage choices" />

:::note
Some CurseForge files still need a manual download when their authors disable
third-party downloads. Ephervex guides you through those files during import.
:::

:::note
If CurseForge gives a download address for a file, Ephervex downloads it, even
when the file is archived or still under review: it is the release the pack
pins. When its author disabled third-party downloads there is no address, and
the file needs the manual download below. A file CurseForge rejected, flagged
as malware, or deleted is refused, because Ephervex never substitutes another
release.
:::

## Import an archive

Inspect the pack before importing. Required files are included automatically;
optional files start off until you select them. New imported instances use
[temporary storage](./instances.mdx#choose-temporary-or-persistent-storage)
unless you choose persistent storage.

<Tabs groupId="interface" queryString="interface">
<TabItem value="gui" label="Desktop" default>

In the host list or on Home, select **Import Modpack**. Choose an archive with
**Browse**, or drop it onto the window. Dropping a file works only on X11 or
XWayland; see [Limitations and Troubleshooting](./troubleshooting.mdx).

<ThemeScreenshot state="file-drop-overlay" alt="The window showing the Drop to import target while an archive is dragged over Ephervex" />

Review the detected pack, Minecraft release, loader, and file counts. Turn on
any optional files you want. You can change the instance name, select **Store
persistently**, and optionally create a linked server from the same pack.
Select **Import Modpack** to begin.

The new instance appears in the host list with a progress bar while the import
runs.

<ThemeScreenshot state="import-modpack-running" alt="The host list showing a modpack import in progress with the download stage and file count" />

The **Activity** card on Home shows current work and the result.

<ThemeScreenshot state="activity-import-in-progress" alt="Home with the modpack import running in the Activity card, a queued operation, and recent results" />

</TabItem>
<TabItem value="cli" label="CLI">

Inspect a local archive without creating an instance:

```bash
ephervex import pack.mrpack --inspect
```

Import it with the pack's own name, or choose a name and persistent storage:

```bash
ephervex import pack.mrpack
ephervex import pack.mrpack --name "Pack Test" --persistent
```

Optional files are off by default. `--inspect` lists their paths. Select one
by repeating `--optional` with its path inside the game directory, or use
`--all-optional` to include them all:

```bash
ephervex import pack.mrpack --optional mods/example.jar
```

`--temporary` explicitly selects the default storage. The CLI import command
creates a client instance; create a linked server separately if you need one.

</TabItem>
</Tabs>

## Import from a link

A pack address must use HTTPS. Ephervex asks before downloading an archive
from a host you have not approved. You can allow one download or remember that
host for later. A redirect to another host needs its own approval. Trusting a
pack host only permits it to serve the archive; it does not change which hosts
may serve files listed inside the pack.

<Tabs groupId="interface" queryString="interface">
<TabItem value="gui" label="Desktop" default>

A website can offer an **Open in Ephervex** link using the
`ephervex://import?url=...` scheme. The pack's HTTPS address is percent-encoded
in the `url` parameter. For example,
[DumpViewer](https://dumps.chaotictrials.de/) ([source](https://github.com/ChaoticTrials/DumpViewer))
can export a stored dump as a Modrinth pack and open it directly in Ephervex.
Confirm the browser's request to open Ephervex, review the pack address and
choose whether to remember its host, then review the normal import dialog.

A link can also carry an `issue` parameter, the percent-encoded address of the
issue or bug report the pack reproduces. The import dialog shows it, and the new
instance keeps it as its issue link. An address that is not a plain `http` or
`https` link is ignored, and the pack still imports.

<ThemeScreenshot state="import-link-trust-prompt" alt="Open a modpack prompt showing the HTTPS address, a switch to remember the site, and Download it" />

Linux packages install the link handler. For an AppImage, register it once
from the command line, using the path to the AppImage you downloaded:

```bash
./Ephervex-x86_64.AppImage url-handler register
./Ephervex-x86_64.AppImage url-handler status
```

Use the `aarch64` file name for the ARM build. Register again if you move the
AppImage. To remove the AppImage's registered handler, run
`url-handler unregister` with the same AppImage command.

You can review or forget remembered hosts under **Settings > General > Sites
allowed to serve modpacks**.

</TabItem>
<TabItem value="cli" label="CLI">

Pass the HTTPS archive address directly:

```bash
ephervex import 'https://example.com/pack.mrpack'
```

An interactive terminal asks about a new host. `--trust once` allows just this
import; `--trust always` remembers the host. In a noninteractive command, one
of these flags is required for a host you have not approved. Neither flag
approves a redirect to a different host in a noninteractive command.

```bash
ephervex import 'https://example.com/pack.mrpack' --trust once
ephervex config pack-hosts
ephervex config pack-hosts --forget example.com
```

`--inspect` on a URL downloads the archive and asks for host approval before
reporting its contents; it does not create an instance.

</TabItem>
</Tabs>

## Rebuild a pack from a crash report or log

LibX can add a SHA1 and a Murmur2 hash for each mod to the `Mod List` of a crash
report. The game prints the same report into `latest.log` when it crashes. From
either file Ephervex creates a client instance for the exact Minecraft release
and Forge or NeoForge build the report names, and installs each mod it can find
by its hash. A file whose mod list has no hashes is refused.

Each hash is looked up in your preferred mod catalog first and in the other one
only for what the first did not have. Set the preferred catalog under
**Settings > Providers & APIs > Preferred catalog**. A mod is matched by its exact file, never
by its name or version. A mod neither catalog can provide is left out and listed
as a warning on the new instance's Overview. The instance still launches, without
that mod. CurseForge is searched only when an
API key is available. The report itself is copied into the instance, so the
logs view and crash review show it.

A report written by a dedicated server still creates a client instance. Mods
the catalog says no client runs are kept for the server side, and the desktop
turns on **Also create a linked server**.

<Tabs groupId="interface" queryString="interface">
<TabItem value="gui" label="Desktop" default>

Select **Import Modpack**, then **Browse**, and choose the crash report or log.
The import dialog shows the mod list and, once the catalogs are searched, the
mods that will be left out.

<ThemeScreenshot state="import-crash-report" alt="Import dialog for a crash report showing its mod list, two mods that will be left out, and a note that CurseForge was not searched" />

</TabItem>
<TabItem value="cli" label="CLI">

Pass the file like an archive. `--inspect` reads it without searching the
catalogs:

```bash
ephervex import crash-2026-11-02_17.08.01-client.txt --inspect
ephervex import logs/latest.log --name "Crash Repro"
```

The command lists the mods it left out after the import.

</TabItem>
</Tabs>

### Match a pack to the log it carries

A pack can carry the reporter's `logs/latest.log` or crash reports in its
overrides. When the log's mod list has hashes and names the pack's own
Minecraft release and loader, Ephervex offers to make the instance match it.
The log is preferred; otherwise the newest crash report with such a list is
used. Applying it adds the mods the pack lacks, replaces a pack mod the list
names at another version, and disables the pack mods the list does not name.
Disabled mods stay in the instance and can be turned back on. A server created
from the instance later installs them again.

<Tabs groupId="interface" queryString="interface">
<TabItem value="gui" label="Desktop" default>

The import dialog asks whether to import the logged mods as well. Neither
answer is preselected, and the pack cannot be imported until you choose.

<ThemeScreenshot state="import-modpack-logged-prompt" alt="Import the logged mods question over the import dialog, naming logs/latest.log, with No and Yes" />

</TabItem>
<TabItem value="cli" label="CLI">

The pack imports as published unless you pass `--logged-mods`:

```bash
ephervex import pack.mrpack --inspect
ephervex import pack.mrpack --logged-mods
```

`--inspect` says when a pack carries such a list.

</TabItem>
</Tabs>

## Resolve files that need a manual download

Some CurseForge authors disable third-party downloads. Ephervex will not
fetch those files automatically or substitute another release. The desktop
import dialog lists each blocked file with its project and file name.

<Tabs groupId="interface" queryString="interface">
<TabItem value="gui" label="Desktop" default>

1. Select **Open in Browser** beside the blocked file, marked in the image.
2. Download the exact file from its provider page and place it in a watched
   download folder. Ephervex matches the file by hash and continues when it
   finds a verified copy.

<ThemeScreenshot state="import-modpack-manual-download" region="blocked-file" callouts={manualDownloadCallouts} alt="Blocked CurseForge file: 1 marks Open in Browser, beside the Skip action" />

Manage watched folders under **Settings > Storage > Watched download
folders**. The Downloads folder is watched by default until you configure the
list.

**Skip** leaves that file out and lists it as a warning on the instance's
Overview. The instance still launches, without that file. Use it only when you
intend to import without the file.

</TabItem>
<TabItem value="cli" label="CLI">

The CLI does not offer the desktop's browser, watcher, and Skip controls. If
a required CurseForge file is blocked and no verified copy is already in the
shared cache, the import fails. Open the pack in the desktop app to resolve or
skip the file, then import there.

</TabItem>
</Tabs>

Imported packs retain their recipe, including server-side files. You can
create a [linked server](./servers.mdx#create-a-server) from the instance later.

## Warnings and problems on an imported instance

An instance's Overview lists what an import could not reproduce. Each entry is
either a warning or a problem.

A **warning** describes something the instance runs without, for example a mod
no catalog could provide or a file you skipped. Launch stays available. A
warning stays listed after you add the file yourself.

A **problem** keeps the instance from launching. Launch is unavailable and its
hint names the first problem. Problems are:

- the instance folder is missing;
- an interrupted change left files that need review;
- the pack uses a loader Ephervex does not support;
- the pack uses launch settings Ephervex cannot reproduce.

The header stamp counts problems only.
