# Themes

Ephervex ships **Dark** and **Light** interface themes. A custom theme is a
TOML file that starts from either built-in theme and changes the colors you
choose. A theme folder can also replace the logo and window icon. Themes
affect Ephervex, not Minecraft. Interface text size and the separate
diagnostics and console text size are set in [General settings](./settings.mdx#general);
themes do not change fonts or layout.

## Choose a theme

Open **Settings > General > Interface theme** and select **Dark**, **Light**,
or a custom theme listed there. The change is saved when selected.

<ThemeScreenshot state="theme-selector-open" alt="General settings with the Interface theme list open, showing Dark, Light, and a custom theme" />

The CLI has no theme selector. Use the desktop app to choose a theme.

## Add a custom theme

Create a TOML file in the folder shown below. The folder does not exist until
you create it:

```text
~/.config/ephervex/themes/my-theme.toml
```

If `XDG_CONFIG_HOME` is set, use
`$XDG_CONFIG_HOME/ephervex/themes/my-theme.toml` instead. **Settings >
General > Interface theme** shows the exact themes folder for this
installation.

Start with a small file:

```toml
format_version = 1
name = "My Theme"
parent = "dark"

[colors]
accent = "#1bd96a"
background = "#16181c"
surface = "#1d1f23"
```

For a complete example, see the [Modrinth theme on GitHub](https://github.com/ChaoticTrials/Ephervex/blob/main/docs/themes/modrinth.toml).
It sets every available color. Copy it into your themes folder as
`modrinth.toml`, then select **Modrinth** under **Interface theme**.

The file name, without `.toml`, is the theme's ID. Use lowercase letters,
digits, `-`, or `_` in the name. A [theme folder](#add-a-logo-and-window-icon)
takes its ID from the folder name instead. The `name` field is the label
shown in the selector. Set `parent` to `"dark"` or `"light"`; omitted colors
come from that parent, including the color scheme used by standard controls.
`format_version`, `name`, `parent`, and `[colors]` may all be omitted. The
defaults are format 1, the file or folder name, Dark, and no overrides. Names
longer than 64 characters are cut to 64.

Colors must be quoted hexadecimal values in `"#rrggbb"` form. Use
`"#rrggbbaa"` when a color needs transparency. Edit the file, then select
**Refresh** in the app's top bar or restart Ephervex. Choose **My Theme**
under **Interface theme**. Renaming a file or folder changes its ID, so
select the renamed theme again.

## Color names

Only colors can be overridden. Use token names exactly as written under
`[colors]`. You can start with `accent`, `background`, and `surface` and
add more when a control needs a different color.

| Tokens | What they color |
| --- | --- |
| `background`, `surface`, `field`, `elevated`, `overlay`, `border`, `bar`, `well` | Page floors, cards, text inputs and dropdowns, popovers, borders, bars, and technical views |
| `selection`, `selection-card`, `selection-strong`, `toggle-on`, `toggle-knob`, `capture-active` | Selected rows, cards, chips, switches (track and knob), and key capture |
| `accent`, `accent-secondary`, `success`, `warning`, `danger` | Focus, links, highlights, and status messages |
| `primary-fill`, `primary-fill-hover`, `danger-fill`, `danger-fill-hover` | Filled buttons and their hover states |
| `text`, `text-secondary`, `text-muted`, `on-primary`, `on-danger`, `log-error` | Text, button captions, and error lines in logs |
| `server`, `modrinth`, `curseforge`, `vanilla`, `forge`, `neoforge` | Server, catalog, and loader marks |
| `group-tone-1` to `group-tone-6` | Instance group labels, one color per group |
| `shadow`, `scrim` | Popover shadows and the wash behind dialogs |

Keep text readable against `background`, `surface`, `field`, and `elevated`.
A primary button uses `on-primary` over `primary-fill`; a destructive button
uses `on-danger` over `danger-fill`. Keep `toggle-knob` distinct from
`toggle-on`, so the knob of a switch that is on stands out from its track.

A theme that sets `accent`, `background`, or `text` and leaves out
`toggle-knob`, `field`, or `on-primary` respectively gives that token the
color it set. Otherwise, omitted colors come from the parent.

Dropdowns, sliders, and spinners use the colors above. Scroll bars, lists, and
the context menus opened by a right-click or a "Launch as" button take no
theme colors. They follow only the light or dark look of the parent, so a
theme with a very different palette can leave them looking out of place.

## Add a logo and window icon

A theme folder replaces the Ephervex logo and window icon with its own images.
Name the folder after the theme's ID and put `theme.toml` and a `branding`
folder in it:

```text
~/.config/ephervex/themes/my-theme/
├── theme.toml
└── branding/
    ├── logo.png
    └── icon.png
```

`theme.toml` uses the same format as a theme file, and a folder without one
is ignored. Name the images in a
`[branding]` section, relative to the `branding` folder:

```toml
[branding]
logo = "logo.png"
icon = "icon.png"
```

| Key | Replaces |
| --- | --- |
| `logo` | The logo in the top bar and on **Settings > About & Licenses** |
| `icon` | The window icon |

Both keys are optional, and each image falls back to the Ephervex logo on its
own. If a theme file and a usable theme folder share a name, the folder is
used. The [Modrinth theme](https://github.com/ChaoticTrials/Ephervex/blob/main/docs/themes/modrinth.toml)
has a commented-out `[branding]` section to start from.

<ThemeScreenshot state="theme-branding" alt="About & Licenses with a theme folder's logo in the top bar and above the version" />

Each image must:

- Be a PNG, JPEG, or WebP file named `.png`, `.jpg`, `.jpeg`, or `.webp`,
  with contents that match the name.
- Be at most 4 MiB and at most 1024 by 1024 pixels.
- Be inside the theme's own `branding` folder, at most three folders deep.
  Leave out `branding/`, and do not use `.`, `..`, a leading `/`, `\`, or
  `:`.
- Be a real file. Ephervex does not follow symbolic links inside a theme
  folder, and skips a theme folder or `theme.toml` that is a link.

Images keep their shape. A logo is fitted to its space, and an icon that is
not square is centered on a transparent square. Ephervex reads only the
selected theme's images, and changing the theme changes the logo right away.

The window icon follows the theme only where the desktop takes it from the
window, such as X11 taskbars that show the window's own icon. On Wayland, and
in docks that show the installed app's icon, such as GNOME Shell, the Ephervex
icon stays. The logo inside the window always follows the theme.

## Fix a theme that does not load

**Settings > General > Interface theme** says how many problems were found in
the themes folder.

<ThemeScreenshot state="theme-load-error" alt="Interface theme setting saying five problems were found, with a Show problems button" />

Select **Show problems** to list them, one line per problem.

<ThemeScreenshot state="theme-problems" alt="Theme problems dialog listing each theme file or folder and what was wrong with it" />

Ephervex skips a file with invalid TOML, an unsupported parent, a newer format
version, a wrong field type, or an invalid color. It also skips a file whose
name uses anything other than lowercase letters, digits, `-`, and `_`, a file
that is not UTF-8 text, and a file that has the same name as a usable theme
folder. Unknown color names, other unknown keys, and `[branding]` entries that
cannot be used are reported and ignored while the rest of the theme loads.
`[branding]` in a standalone file is always ignored, because only a theme
folder has a `branding` folder. A branding image that cannot be shown is
listed with its path, and the Ephervex logo is shown instead.

Theme files are limited to 64 KiB each, and Ephervex reads at most 100 themes,
files and folders together. If the selected theme cannot be read, Ephervex
uses Dark while keeping the choice; fix the file and select **Refresh** to
bring it back.
