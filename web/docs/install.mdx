Ephervex ships a desktop app and CLI for Linux. Choose a package for your
distribution, or use the AppImage without installing a package.

## Debian and Ubuntu

Add the signed ChaoticTrials APT repository, then install Ephervex. These
commands are the same on x86_64 and aarch64: APT selects `amd64` or `arm64`
for your system automatically.

```bash
curl -fsSL https://repo.chaotictrials.de/apt-keyring.gpg \
  | sudo tee /usr/share/keyrings/chaotictrials.gpg > /dev/null
echo "deb [signed-by=/usr/share/keyrings/chaotictrials.gpg] \
https://repo.chaotictrials.de/deb stable main" \
  | sudo tee /etc/apt/sources.list.d/chaotictrials.list > /dev/null
sudo apt update
sudo apt install ephervex
```

APT will include Ephervex in later package updates. The package installs
`ephervex` and `ephervex-gui` on your command path and adds Ephervex to the
application menu.

Alternatively, download the `.deb` for your architecture from the
[GitHub releases page](https://github.com/ChaoticTrials/Ephervex/releases).
Replace `VERSION` with the number in its filename, then install the matching
package. The example uses the x86_64 filename; on ARM, replace `amd64` with
`arm64`:

```bash
sudo apt install ./ephervex_VERSION_amd64.deb
```

The direct download does not add the repository, so install later versions from
their release packages.

## AppImage

Download the AppImage matching your architecture from the
[GitHub releases page](https://github.com/ChaoticTrials/Ephervex/releases) and
make it executable. The commands below use the x86_64 filename; on ARM, replace
`x86_64` with `aarch64`:

```bash
chmod +x Ephervex-x86_64.AppImage
```

It runs without a package installation. Keep it in a location where you want
to run it, and do not run it with `sudo`.

### If FUSE is unavailable

The AppImage needs `/dev/fuse` and a `fusermount` helper on your command path.
If it cannot mount, install your distribution's FUSE package or use:

```bash
APPIMAGE_EXTRACT_AND_RUN=1 ./Ephervex-x86_64.AppImage
```

This extracts the AppImage into a temporary directory each time it starts and
works without FUSE. You can also use this environment variable with the CLI
commands below.

## Fedora and other RPM distributions

On Fedora and other distributions using DNF 5, add the signed ChaoticTrials
repository, then install Ephervex:

```bash
sudo dnf config-manager addrepo --from-repofile=https://repo.chaotictrials.de/rpm/chaotictrials.repo
sudo dnf install ephervex
```

On DNF 4, replace the first command with:

```bash
sudo dnf config-manager --add-repo https://repo.chaotictrials.de/rpm/chaotictrials.repo
```

DNF will include Ephervex in later package updates.

Alternatively, download the `.rpm` matching your architecture from the
[GitHub releases page](https://github.com/ChaoticTrials/Ephervex/releases).
Replace `VERSION` with the number in its filename. The commands below use the
x86_64 filename; on ARM, replace `x86_64` with `aarch64`. On Fedora or another
distribution using DNF:

```bash
sudo dnf install ./ephervex-VERSION-1.x86_64.rpm
```

On openSUSE, install the release RPM with Zypper:

```bash
sudo zypper install ./ephervex-VERSION-1.x86_64.rpm
```

The package installs both commands and an application menu entry. A direct RPM
download does not add the repository, so install later versions from their
release packages.

## Requirements

<Admonition type="note" title="ARM support">
  Ephervex runs on ARM (aarch64). Minecraft needs compatible ARM native
  libraries for the version you choose; versions without them are refused.
  ARM launches have not been tested yet, so try it and see.
</Admonition>

- Linux with **glibc 2.35 or newer**, such as Ubuntu 22.04 or Debian 12.
- An x86_64 or aarch64 system.
- X11 or XWayland for the desktop application. A Wayland session without
  XWayland is untested.
- FUSE for the AppImage, or the extraction option described above.

Run `uname -m` in a terminal to check your architecture:

| `uname -m` | AppImage | Debian package | RPM |
| --- | --- | --- | --- |
| `x86_64` | `Ephervex-x86_64.AppImage` | `ephervex_VERSION_amd64.deb` | `ephervex-VERSION-1.x86_64.rpm` |
| `aarch64` | `Ephervex-aarch64.AppImage` | `ephervex_VERSION_arm64.deb` | `ephervex-VERSION-1.aarch64.rpm` |

`VERSION` stands for the release number in a downloaded package filename.
Use the package for your architecture, and run file installation commands from
the directory containing the download.

To check a direct download, save its matching `.sha256` file in the same
directory and run, for example:

```bash
sha256sum --check Ephervex-x86_64.AppImage.sha256
```

Continue only if the check reports `OK`. If it fails, download the artifact
and its checksum again from the same release.

## Start Ephervex

<Tabs groupId="interface" queryString="interface">
<TabItem value="gui" label="Desktop" default>

For a package installation, open **Ephervex** from your application menu, or
run:

```bash
ephervex-gui
```

For the AppImage, run it without arguments:

```bash
./Ephervex-x86_64.AppImage
```

Use **New Instance** to create an environment, or **Import Modpack** to load
an existing pack. The [interface tour](./interface-tour.mdx) shows
these controls.

</TabItem>
<TabItem value="cli" label="CLI">

For a package installation:

```bash
ephervex --help
ephervex doctor
```

For the AppImage, pass the command as an argument:

```bash
./Ephervex-x86_64.AppImage --help
./Ephervex-x86_64.AppImage doctor
```

To make the AppImage available as `ephervex`, you can create a symlink from
the directory containing it:

```bash
mkdir -p ~/.local/bin
ln -s "$PWD/Ephervex-x86_64.AppImage" ~/.local/bin/ephervex
```

Ensure `~/.local/bin` is on your `PATH`. The absolute target keeps the link
valid, and the name `ephervex` selects the command-line interface even when no
arguments are given.

</TabItem>
</Tabs>

## Check the installation

Run `ephervex doctor`, or the AppImage's `doctor` command above, for a local
health report. It checks storage locations, configuration, and the environment
Ephervex needs. It does not download or launch Minecraft and does not change
your configuration.

A nonzero exit status means the report found a fault. Read the affected check
and fix the reported problem before trying again. A directory reported as
missing and created on first use is normal on a fresh installation.
